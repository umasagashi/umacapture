プライバシーポリシー

umacapture（以下「このアプリ」）が、利用する人の情報をどのように扱うかを説明します。このページの内容は、Windows 版と web 版の両方に当てはまります。

このアプリは、ログインしなくても、レコードの共有と端末間の同期のほかはすべての機能を使えます。画面や動画の認識は、お使いの端末の中で行います。

2. ログイン

レコードの共有と端末間の同期を使うときだけ、Google アカウントでのログインが要ります。

ログインのとき、Google から、あなたの Google アカウントを識別する番号とメールアドレスを受け取ります。

サーバーに保存するのは、その番号から作った、元に戻せない値（ハッシュ）だけです。Google アカウントの番号そのもの、メールアドレス、名前、アイコンは、サーバーに保存しません。

メールアドレスは、受け取ったその場で一部を伏せた形（例: ke****@gmail.com）にして、あなたの端末にだけ渡します。端末はこれを保存し、ログインしていないときに、どのアカウントでログインしていたかを示すために表示します。ログアウトするか、アカウントを削除すると、端末から消えます。

ログインすると、このアプリのアカウントが作られ、公開の番号が付きます。この番号は、あなたが共有したレコードの一覧のページの URL（/u/<番号>）に使われます。

ログインしたとき、自分で育成したレコードを見分けるために、その端末で作った無作為の番号（トレーナー ID）をアカウントに登録します。1 つのアカウントに登録できるのは 20 件までで、アカウントを削除するまで保存します。

3. Google と Cloudflare Turnstile

ログインの画面は Google が表示します。そこでの情報の扱いは、Google のプライバシーポリシー（https://policies.google.com/privacy）に従います。

ログインを始める前と、共有のページや一覧のページから問題を報告する前に、bot でないことの確認（Cloudflare Turnstile）があります。このとき Cloudflare が、IP アドレスやブラウザの情報を処理します（https://www.cloudflare.com/turnstile-privacy-policy/）。

4. 共有で保存・公開されるもの

レコードを共有すると、そのレコードのデータを、あなたのアカウントのものとして、共有した日付とともにサーバーに保存します。

共有したレコードは、URL を知っている人なら誰でも見られます。個別のページ、外部のツール向けの JSON、X や Discord に表示されるカード画像、このアプリに取り込むためのデータとして公開されます。

共有するときに「画像も共有する」を選ぶと、そのレコードの画像も保存し、公開します。公開するのは、認識に使った画像（ゲーム画面の一部をつないだもの）を縮小したものと、一覧のアイコンです。画像は共有のページやカード画像には出しませんが、URL を知っている人なら誰でも取り出せます。

あなたが共有したレコードは、1 つの一覧のページ（/u/<番号>）にまとめて表示されます。Google アカウントの名前やメールアドレスは出ませんが、同じ人が共有したものだということは分かります。

「アカウント」タブの公開プロフィールにトレーナー名やゲーム内のトレーナー ID を書くと、一覧のページと、あなたが共有したすべてのレコードのページに表示されます。共有したレコードごとに書ける宣伝文句は、そのレコードのページと一覧に表示されます。どちらもそれぞれの JSON に含まれますが、カード画像や X・Discord の説明文には出さず、ほかの人がアプリに取り込んだものにも含まれません。

公開される項目: 育成ウマ娘（衣装・ランク・アイコンの種類）、レコードの種類（通常／継承用）、評価点、ステータス、適性、作戦、スキル、因子、サポートカード、継承元（アイコンの種類・ランク・レコードの種類）、重賞ボーナス、ファン数、シナリオ、戦績、育成日、共有した日付、認識に使った認識モジュールの版、書いた場合は宣伝文句・トレーナー名・ゲーム内のトレーナー ID。

公開されない項目: メモと評価、撮影日時、端末のトレーナー ID（項目 2）、画像（「画像も共有する」を選ばなかったとき）。

共有できるのは、自分で育成したレコードだけです。ほかの人の育成のレコードや画像は共有しないでください。公開プロフィールや宣伝文句に、ほかの人の名前や ID を書かないでください。

共有したレコードは、ほかの人がこのアプリに取り込めます。取り込まれたものは、共有を取り消しても消えません。

共有のページは、検索エンジンに載らないように設定しています。ただし、URL を共有した先からは誰でも開けます。

5. 共有の取り消し

共有は、同じ Google アカウントでログインすれば、どの端末からでも取り消せます。

取り消しても、X や Discord などに残った表示や、ほかの人が保存したものは消せません。

取り消すと、共有した画像と宣伝文句もサーバーから削除します。

取り消した後も、カード画像は、配信の途中に置かれた写し（1 時間をめどに作り直す設定です）や、見た人のブラウザに残った写しから、しばらく表示されることがあります。

共有したレコードは、共有した時点の写しです。その後に同期でレコードが変わっても、共有した内容と URL は変わりません。

宣伝文句と公開プロフィールは、後から書き換えたり消したりできます。ページへの反映には数分かかります。書き換える前の内容は、運営者のバックアップに最大 30 日間残ります（項目 6）。

運営者は、報告などを受けて、共有や共有した画像を取り消したり、公開プロフィールを消したりすることがあります。

取り消した共有のデータは、運営者のバックアップに最大 30 日間残ります（項目 6）。

6. アカウントの削除

アカウントは「アカウント」タブから削除できます。

削除すると、このアカウント（公開プロフィールを含みます）と、このアカウントで共有したレコード（共有した画像と宣伝文句を含みます）・同期したデータをすべてサーバーから削除し、すべての端末でログアウトします。削除は元に戻せません。端末のレコードは消えません。

レコードを削除したときのような 7 日の保持はありません。同期のデータは、差し替えられた古い一覧表や、消えるのを待っているものも含めて、すべて削除します。

1 日に使える処理の量に上限があるため、削除は日をまたぐことがあります。削除の途中は、どの端末からも共有や同期はできません。

削除が完了した時点で、あなたのデータはサーバーから消えています。ただし、削除を始めたときに動いていた同期や共有の画像の送信、サーバーが 1 時間ごとに行う処理が、削除の後に書き込んだものが残ることがあります。これはサーバーが 1 時間ごとの処理で自動で消し、通常は数時間以内に消えます。

サーバーのデータベースには、障害に備えて過去 30 日以内の時点に戻せる仕組みがあります。このため、削除したデータのうちデータベースにあったものは、削除の後も最大 30 日間、運営者のバックアップに残ります。

7. ログインの状態の保存

ログインの状態は、Windows 版ではアプリのデータに、web 版ではブラウザのサイトデータに保存します。

サーバーには、ログインの状態を確かめるための値を、元に戻せない形（ハッシュ）にして保存します。ログインの状態は 180 日で切れます。ログアウトすると、その端末のログインの状態はサーバーからも消えます。

8. 利用しているサービス

  • Cloudflare: このサイトの配信と、アカウント・共有したレコード・同期の管理情報の保存（Cloudflare Workers・D1）、ログインと報告の前の確認（Turnstile）に使っています。配信事業者として、アクセスの情報（IP アドレスなど）を処理します。このサイトのサーバーでは、運営者がアクセスの記録を残す機能（Workers のログ）を無効にしています。
  • Vercel: 共有したレコードのカード画像（X や Discord に表示される画像）を作ります。使うのは公開済みのデータだけです。作った画像は、配信のために Vercel に一時的に保存されます（1 時間をめどに作り直す設定です）。画像の配信のため、アクセスの情報（IP アドレスなど）を処理します。
  • Google: ログイン（項目 2・3）と、フォントの配信（項目 9）に使っています。
  • Backblaze: 端末間の同期のデータ（一覧表・本文・画像）と、共有した画像を保存します（Backblaze B2、米国西部）。項目 12 をご覧ください。
  • Sentry: エラー報告と、報告・フィードバックの受け取りに使っています（項目 9）。
  • GitHub: Windows 版の更新の確認に使っています（項目 9）。

9. エラー報告と、外部から取得するもの

エラー報告: アプリで起きたエラーの情報を Sentry に送ります。初回の起動から送信されます。「設定」の「プライバシー設定」にある「利用環境情報の送信許可」をオフにすると送らなくなります（次にアプリを起動したときから反映されます）。

送る内容は、エラーの内容と発生箇所、その直前のアプリの動作記録、アプリの版、端末の情報（Windows 版では OS の種類など、web 版ではブラウザの識別文字列〔ブラウザと OS の種類を含みます〕と、開いているページの URL）などです。ファイルの場所に含まれる名前は伏せて送ります。送信元の区別には、その端末で作った無作為の番号を使います（「利用環境情報の送信許可」をオフにすると消えます）。

web 版では、エラー報告の仕組みを Sentry の配信元（browser.sentry-cdn.com）から読み込みます。

報告とフィードバック: 誤認識報告・キャプチャエラー報告・取り込みエラー報告を送ると、報告の画面に示したもの（レコードの記録ファイルと画像、画面の画像、動画から選んだ 1 コマの画像など）を Sentry に送ります。フィードバックを送るときは、スクリーンショットが付くことがあります。共有のページの「問題を報告」から送ると、その共有の番号と共有した日付、選んだ理由、書いた文を Sentry に送ります。共有レコードの一覧のページから送ると、共有の番号と日付の代わりに一覧の番号を送ります。報告は匿名です。返信はありません。どれも、あなたが送る操作をしたときだけ送ります。

フォント: 文字を表示するためのフォントを Google（fonts.gstatic.com）から取得します。このとき IP アドレスなどが Google に渡ります。

認識モジュール・お知らせ: data.umacapture.com（運営者のサーバー）から取得します。

更新の確認（Windows 版のみ）: 新しい版があるかを GitHub（github.com）に問い合わせます。

アドオン: アドオンで webhook や外部のプログラムを設定した場合は、あなたが指定した宛先へ送ります。

11. 端末間の同期で保存されるもの

端末間の同期は、オンにしている間だけ動く機能で、Google アカウントでのログインが要ります（オフにしたときに動いていた同期は、最後まで続きます — 項目 16）。オンにすると、次のものがサーバーに保存され、同じアカウントでログインしたあなたのほかの端末に届きます。ほかの人には公開しません（運営者が見られることは項目 13）。

  • 一覧表: 各レコードの ID、アーカイブの状態、継承元の ID、統合で取り込んだレコードの ID、レコードの画像を識別する値（ハッシュ）、評価とメモ（それぞれを書いた時刻とともに）、表の列の名前、統合の候補から外した組。
  • 本文: 各レコードの認識の結果（育成ウマ娘・ステータス・スキル・因子など）と、撮影日時、トレーナー ID、レコードの画像を識別する値。
  • 画像: 「画像の同期」の設定に従います。「元の画像」か「縮小した画像」を選ぶと、認識に使った画像（ゲーム画面の一部をつないだもの）と、一覧のアイコンを送ります。初めは「画像は送らない」になっていて、この設定では画像もアイコンも送りません。

「画像は送らない」でも、一覧表と本文は送ります。

ただし「画像は送らない」でも、縮小 JPEG でアーカイブしたレコードは、サーバーにある元の画像（PNG）を縮小した画像（JPEG）に置き換えるため、その縮小した画像を送ります。

「画像は送らない」に変える前に送った画像は、サーバーに残ります。

同期が途中で失敗したときや途中で切れたときに送った一覧表も、そのときの評価やメモを含んだまま、しばらくサーバーに残ります（項目 14）。

12. 同期のデータの保存先

同期のデータは、Cloudflare D1（アカウントの情報と、同期の管理情報）と Backblaze B2（米国西部。一覧表・本文・画像）に保存します。

あなたの端末は Backblaze と直接は通信しません。送受信はすべてこのサイトのサーバーを通ります。

Cloudflare D1 に保存したもの（アカウントの情報と、同期の管理情報）は、削除した後も最大 30 日間、運営者のバックアップに残ります（項目 6）。

13. 同期のデータを見られる人

同期のデータを見られるのは、そのアカウントでログインしているあなただけです。共有とは別のもので、ほかの人には公開しません。

ただし、このアプリはデータを暗号化してから送る仕組みを持たないため、運営者はサーバーの管理者として内容を見られる状態にあります。

14. 同期のデータの削除

同期をオンにした端末でレコードを削除すると、次の同期でサーバーの一覧表から消え、ほかの端末からも消えます。

そのレコードの本文と画像は、サーバーの一覧表のどのレコードからも使われなくなった時点で、サーバーの中で見えない状態にし、最長 7 日で消えます。同じ画像をほかのレコードも使っているときは、そのレコードが一覧表にある間、画像も残ります。

差し替えられた古い一覧表（前の評価やメモ、削除したレコードの情報を含みます）と、同期が途中で失敗したときや切れたときに送った一覧表も、使われなくなった時点から同じように消えます（送ったまま使われなかったものは、送ってから 15 分たった後に見えない状態にします）。

縮小 JPEG でアーカイブしたレコードの元の画像（PNG）は、縮小した画像（JPEG）がサーバーに届き、サーバーの一覧表でそのレコードがアーカイブ済みになった後、ほかのレコードがその元の画像を使っていなければ、同じように消えます。その後はサーバーから元の画像を取り戻せません。容量がいっぱいで縮小した画像を送れない間は、元の画像を残します。

統合で取り込まれたレコードの ID は、統合後のレコードがある間、その「取り込んだ ID」としてサーバーに残ります。

アカウントを削除したときは、項目 6 のとおりです。

15. 同期の上限

1 つのアカウントで同期できるのは、5,000 件、2 GiB までです（元の画像ならおよそ 500 件、縮小した画像ならおよそ 2,000 件に当たります）。サーバー全体にも保存量の上限があります。

保存量が上限に達すると、容量を使う同期（新しいレコード・画像・統合）は、空きができるまで待ちます。削除やアーカイブなど、容量を使わない同期は進みます。

見えない状態にして消えるのを待っているもの（項目 14）にも、1 つのアカウントあたり 2 GiB の上限があります。これを超えると、新しい画像などを送る同期は待ちます。待っているものは、見えない状態にした日（協定世界時）から 6〜7 日たつと数えなくなり、その分が空きます。削除をしても早く空くことはなく、削除した分はかえって加わります。

縮小 JPEG でアーカイブすると、置き換えが済んだ時点で、元の画像の分はアカウントの保存量から外れます（ほかのレコードがその元の画像を使っている場合を除きます）。外れた分は、上の「消えるのを待っているもの」に数えます。保存量がいっぱいのときは、縮小した画像を送れないため、置き換えそのものが待ちます。

1 日に同期できる量にも、1 つのアカウントあたりと、サーバー全体の上限があります（日付は協定世界時で変わります）。上限に達すると、同期は翌日に続きから再開します。その日のうちに終わることは約束しません。

上限に達しても、アプリのほかの機能は止まりません。

16. 同期をオフにしたとき

同期をオフにすると、その端末は新しく同期を始めません。オフにしたときに同期が動いていた場合は、その回は最後まで続き、レコードや画像を送ることがあります。そのほかに、オフの間にその端末からサーバーへレコードを送ることはありません（同期をオンにする画面を開いたときは、件数と画像の設定を示すために、サーバーの一覧表と設定を読みます）。

端末のレコードは、そのまま残ります。サーバーのデータも残ります。サーバーのデータをすべて消すには、アカウントを削除してください。

オフの間にその端末で変えたこと（削除を含みます）は、もう一度オンにしたときにサーバーへ反映されます。オフの間も、ほかの端末で同期を続けていれば、そこでの削除や項目 14 の期限によって、サーバーのものは消えます。
