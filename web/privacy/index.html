プライバシーポリシー

umacapture（以下「このアプリ」）の利用者情報の扱いを説明します。このページの内容は、Windows 版と web 版の両方に当てはまります。

レコードの共有と端末間の同期以外は、ログインせずに使えます。画面や動画の認識は、お使いの端末の中で行います。

2. ログイン

レコードの共有と端末間の同期を使うときだけ、Google アカウントでのログインが要ります。

ログイン時に、Google からアカウントの識別番号とメールアドレスを受け取ります。

サーバーに保存するのは、その番号から作ったハッシュ値だけです。Google アカウントの番号そのもの、メールアドレス、名前、アイコンは、保存も表示もしません。

ログイン日（協定世界時）をアカウントに保存し、項目 6 の自動削除に使います。

ログインするとアカウントが作られ、共有レコード一覧の URL（/u/<番号>）に使う公開番号が付きます。

ログイン時、自分で育成したレコードを見分けるため、端末で作った無作為の番号（トレーナー ID）をアカウントに登録します。1 つのアカウントに登録できるのは 20 件までで、アカウントを削除するまで保存します。

3. Google と Cloudflare Turnstile

Google が表示するログイン画面での情報の扱いは、Google のプライバシーポリシー（https://policies.google.com/privacy）に従います。

ログインを始める前と、共有のページや一覧のページから問題を報告する前に、bot でないことの確認（Cloudflare Turnstile）があります。このとき Cloudflare が、IP アドレスやブラウザの情報を処理します（https://www.cloudflare.com/turnstile-privacy-policy/）。

4. 共有で保存・公開されるもの

レコードを共有すると、そのレコードのデータを、あなたのアカウントのものとして、共有した日付とともにサーバーに保存します。

共有したレコードは、URL を知っている人なら誰でも見られます。個別のページ、外部のツール向けの JSON、X や Discord に表示されるカード画像、このアプリに取り込むためのデータとして公開されます。

共有するときに「画像も共有する」を選ぶと、そのレコードの画像も保存し、公開します。公開するのは、認識に使った画像（ゲーム画面の一部をつないだもの）を縮小したものと、一覧のアイコンです。画像は共有のページやカード画像には出しませんが、URL を知っている人なら誰でも取り出せます。

「アカウント」タブで一覧を公開すると、共有したレコードが一覧ページ（/u/<番号>）にまとまります。Google アカウントの名前やメールアドレスは出ませんが、同じ人が共有したものだということは分かります。一覧のページは、公開するまで非公開です。非公開のあいだは、開いても「この一覧は非公開です」とだけ表示されます。一覧を非公開にしても、個々のレコードのページは公開されたままです。

「アカウント」タブの公開プロフィールにトレーナー名やゲーム内のトレーナー ID を書くと、あなたが共有したすべてのレコードのページと、公開している一覧のページに表示されます。共有したレコードごとに書ける公開メモは、そのレコードのページと、公開している一覧に表示されます。どちらもそれぞれの JSON に含まれますが、カード画像や X・Discord の説明文には出さず、ほかの人がアプリに取り込んだものにも含まれません。

公開される項目: 育成ウマ娘（衣装・ランク・アイコンの種類）、レコードの種類（通常／継承用）、評価点、ステータス、適性、作戦、スキル、因子、サポートカード、継承元（アイコンの種類・ランク・レコードの種類）、重賞ボーナス、ファン数、シナリオ、戦績、育成日、共有した日付、認識に使った認識モジュールの版、書いた場合は公開メモ・トレーナー名・ゲーム内のトレーナー ID。

公開されない項目: メモと評価、撮影日時、端末のトレーナー ID（項目 2）、画像（「画像も共有する」を選ばなかったとき）。

自分で育成したレコードだけを共有し、ほかの人の画像は共有しないでください。公開プロフィールや公開メモに、ほかの人の名前や ID を書かないでください。

共有したレコードは、ほかの人がこのアプリに取り込めます。取り込まれたものは、共有を取り消しても消えません。

共有のページは、検索エンジンに載らないように設定しています。

5. 共有の取り消し

共有は、同じ Google アカウントでログインすれば、どの端末からでも取り消せます。

取り消しても、X や Discord などに残った表示や、ほかの人が保存したものは消せません。

取り消すと、共有した画像と公開メモもサーバーから削除します。

取り消した後も、カード画像は、配信の途中に置かれた写し（1 時間をめどに作り直す設定です）や、見た人のブラウザに残った写しから、しばらく表示されることがあります。

共有したレコードは共有時点の写しで、その後に同期で変わっても、共有内容と URL は変わりません。

公開メモと公開プロフィールは、後から書き換えたり消したりできます。ページへの反映には数分かかります。書き換える前の内容は、運営者のバックアップに最大 30 日間残ります（項目 6）。一覧のページの公開・非公開も、後から切り替えられます。反映には 1 分ほどかかります。

運営者による取り下げや消去については、利用規約の項目 3 をご覧ください。

取り消した共有のデータは、運営者のバックアップに最大 30 日間残ります（項目 6）。

6. アカウントの削除

アカウントは「アカウント」タブから削除できます。

削除すると、このアカウントと公開プロフィール、このアカウントの共有レコード・画像・公開メモ、同期データをすべてサーバーから削除し、全端末でログアウトします。削除は元に戻せません。端末のレコードは消えません。

どの端末からも 365 日間ログインしないと、アカウントを自動で削除します。削除の範囲と進み方は、自分で削除したときと同じです。メールなどでの予告はしません（連絡先を保存していないためです）。そのアカウントにログインしたことがある未ログインの端末では、削除の 30 日前から前日まで、アプリの起動時にお知らせします。

アカウント削除では 7 日間保持せず、古い一覧表や削除待ちのデータも含め、同期データをすべて削除します。

1 日の処理量に上限があるため、削除は日をまたぐことがあります。削除の途中は、どの端末からも共有や同期はできません。

削除が完了した時点で、あなたのデータはサーバーから消えています。ただし、削除を始めたときに動いていた同期や共有の画像の送信、サーバーが 1 時間ごとに行う処理が、削除の後に書き込んだものが残ることがあります。これはサーバーが 1 時間ごとの処理で自動で消し、通常は数時間以内に消えます。

障害復旧のため、サーバーのデータベースは過去 30 日以内の状態に戻せます。このため、削除したデータベース内のデータは、最大 30 日間、運営者のバックアップに残ります。

7. ログインの状態の保存

ログインの状態は、Windows 版ではアプリのデータに、web 版ではブラウザのサイトデータに保存します。

サーバーには、ログインの状態を確かめるための値を、元に戻せない形（ハッシュ）にして保存します。ログインの状態は 180 日で切れます。ログアウトすると、その端末のログインの状態はサーバーからも消えます。

ログアウト後も端末は、お知らせのため、最後にログインしたアカウントの番号・最終ログイン日・削除日を覚えています。その端末からアカウントを削除すると忘れます。

8. 利用しているサービス

  • Cloudflare: このサイトの配信と、アカウント・共有したレコード・同期の管理情報の保存（Cloudflare Workers・D1）、ログインと報告の前の確認（Turnstile）に使っています。配信事業者として、アクセスの情報（IP アドレスなど）を処理します。このサイトのサーバーでは、運営者がアクセスの記録を残す機能（Workers のログ）を無効にしています。
  • Vercel: 公開済みデータだけで、共有レコードのカード画像（X・Discord に表示する画像）を作ります。作った画像は、配信のために Vercel に一時的に保存されます（1 時間をめどに作り直す設定です）。画像の配信のため、アクセスの情報（IP アドレスなど）を処理します。
  • Google: ログイン（項目 2・3）と、フォントの配信（項目 9）に使っています。
  • Backblaze: 端末間の同期のデータ（一覧表・本文・画像）と、共有した画像を保存します（Backblaze B2、米国西部）。項目 11 をご覧ください。
  • Sentry: エラー報告と、報告・フィードバックの受け取りに使っています（項目 9）。
  • GitHub: Windows 版の更新の確認に使っています（項目 9）。

9. エラー報告と、外部から取得するもの

エラー報告: 初回起動から、アプリのエラー情報を Sentry に送ります。「設定」→「プライバシー設定」→「利用環境情報の送信許可」をオフにすると、次回起動から送信を止めます。

送る内容は、エラーの内容と発生箇所、その直前のアプリの動作記録、アプリの版、端末の情報（Windows 版では OS の種類など、web 版ではブラウザの識別文字列〔ブラウザと OS の種類を含みます〕と、開いているページの URL）などです。ファイルの場所に含まれる名前は伏せて送ります。送信元の区別には、その端末で作った無作為の番号を使います（「利用環境情報の送信許可」をオフにすると消えます）。

web 版では、エラー報告の仕組みを Sentry の配信元（browser.sentry-cdn.com）から読み込みます。

報告とフィードバック: 誤認識報告・キャプチャエラー報告・取り込みエラー報告を送ると、報告の画面に示したもの（レコードの記録ファイルと画像、画面の画像、動画から選んだ 1 コマの画像など）を Sentry に送ります。フィードバックを送るときは、スクリーンショットが付くことがあります。共有のページの「問題を報告」から送ると、その共有の番号と共有した日付、選んだ理由、書いた文を Sentry に送ります。共有レコードの一覧のページから送ると、共有の番号と日付の代わりに一覧の番号を送ります。報告は匿名で、返信はありません。どれも、あなたが送る操作をしたときだけ送ります。

フォント: 文字を表示するためのフォントを Google（fonts.gstatic.com）から取得します。このとき IP アドレスなどが Google に渡ります。

認識モジュール・お知らせ: data.umacapture.com（運営者のサーバー）から取得します。

更新の確認（Windows 版のみ）: 新しい版があるかを GitHub（github.com）に問い合わせます。

アドオン: アドオンで webhook や外部のプログラムを設定した場合は、あなたが指定した宛先へ送ります。

11. 端末間の同期

同期をオンにしている間、次のものをサーバーに保存し、同じアカウントでログインしたあなたのほかの端末に届けます。

  • 一覧表: 各レコードの ID とアーカイブの状態、評価とメモ（書いた時刻とともに）、表の列の名前など、レコードを整理するための情報。
  • 本文: 各レコードの認識の結果、撮影日時、トレーナー ID。
  • 画像: 認識に使った画像と一覧のアイコン。「画像の同期」で「元の画像」「縮小した画像」「画像は送らない」を選べます（初めは「縮小した画像」で、オンにする前に選び直せます）。「画像は送らない」でも、元の画像をすでにサーバーに送ったレコードを縮小 JPEG でアーカイブすると、その元の画像を置き換えるため、縮小した画像を送ります。「画像は送らない」に変える前に送った画像は、サーバーに残ります。

保存先は Cloudflare D1（アカウントと同期の管理情報）と Backblaze B2（米国西部。一覧表・本文・画像）で、端末との送受信はすべてこのサイトのサーバーを通ります。同期のデータを見られるのは、そのアカウントでログインしたあなただけです。ただし、このアプリはデータを暗号化してから送る仕組みを持たないため、運営者はサーバーの管理者として内容を見られる状態にあります。

12. 同期のデータが消えるとき

端末でレコードを削除すると、次の同期でほかの端末からも消えます。削除したレコードの本文と画像は、どのレコードからも使われなくなってから最長 7 日でサーバーから消えます。差し替えられた古い一覧表（前の評価やメモを含みます）、途中で失敗・中断した同期で送ったもの、縮小 JPEG に置き換えた元の画像も同じです。Cloudflare D1 に保存したものは、削除の後も最大 30 日間、運営者のバックアップに残ります（項目 6）。

同期をオフにすると、その端末は新しく同期を始めず、レコードを送りません。同期をオンにする画面を開いたときは、件数と画像の設定を示すために、サーバーの一覧表と設定を読みます。ただし、オフにしたときに動いていた回は最後まで続きます。端末とサーバーのデータは残ります。オフの間の変更（削除を含みます）は、次にオンにしたときに反映されます。ほかの端末で同期を続けていれば、そこでの削除はサーバーにも反映されます。サーバーのデータをすべて消すには、アカウントを削除してください。項目 6 の自動の削除は、オフの間も行われます。

13. 同期の上限

1 つのアカウントで同期できるのは、5,000 件、2 GiB までです。サーバー全体の保存量と、1 日に同期できる量（アカウントごとと、サーバー全体。日付は協定世界時で変わります）にも上限があります。上限に達すると、容量を使う同期は空きができるまで、1 日の量を使い切った同期は翌日まで待ちます。アプリのほかの機能は止まりません。
