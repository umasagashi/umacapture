# アドオン ユーザーマニュアル

アドオンは、アプリの**イベント**（キャプチャ完了など）や**手動操作**をきっかけに、
あなたが決めた**処理**を自動で実行する機能です。
「タスク」を登録しておくと、条件がそろったときに外部プログラムやアプリ内蔵の処理が走ります。

> このマニュアルは、キャプチャや殿堂入り管理の使い方は分かっている方向けです。
> プログラミングの知識がなくても、外部プログラム連携と内蔵アクションはここに書かれた範囲だけで使えます。

## 1. アドオンとは（タスク = トリガ + アクション）

アドオンの中心になるのが**タスク**です。1 つのタスクは、次の 2 つを組み合わせたものです。

- **トリガ** … *いつ*実行するか（例: 「レコード取得時」「手動実行のみ」）
- **アクション** … *何を*実行するか（例: 外部プログラムを起動する／通知を出す）

ナビバー左側の **「アドオン」タブ（🧩 拡張機能アイコン、「殿堂入り管理」と「設定」の間）** で
タスクを登録・管理します。

トリガの条件がそろうと、**有効になっているタスクのうちトリガが一致するものがすべて**実行されます。
同じトリガに複数のタスクを登録すれば、まとめて実行されます。

## 2. アドオンタブの画面

アドオンタブは 3 つのカードで構成されます。

| カード | 内容 |
| --- | --- |
| **タスク** | 登録済みタスクの一覧。各タスクの有効/無効、手動実行、編集ができます。右上の「＋」で新規追加。 |
| **実行中** | いま動いているタスク。進捗インジケータと中止ボタンが出ます。実行中のタスクが無いときは表示されません。 |
| **実行履歴** | 過去の実行結果（成功/失敗/中止/タイムアウト）。最新のものが上に並びます。右上のボタンで全消去。 |

## 3. タスクを作る・編集する・消す

### 追加

1. **タスク**カード右上の **「＋」** を押します。
2. ダイアログで次を設定します。
   - **タスク名** … 一覧や履歴に表示される名前（必須）。
   - **トリガ** … いつ実行するか（[4 章](#4-トリガいつ実行するか)）。
   - **アクション種別** … 「外部プログラム」または「アプリ内蔵アクション」。
   - 種別ごとの設定（[6 章](#6-アクション外部プログラム) / [7 章](#7-アクションアプリ内蔵)）。
3. **「保存」** を押します。名前が空、または外部プログラムでパスが空のときは保存できません。

### 編集

タスク一覧の**行をタップ**すると編集ダイアログが開きます。同じ画面から **「削除」** もできます。

### 有効/無効の切り替え

各行の**左のスイッチ**で切り替えます。**無効のタスクはトリガが来ても自動実行されません**
（手動実行ボタンは押せます）。

### 手動で今すぐ実行

各行の**右の ▶ ボタン**で、トリガに関係なくその場で 1 回実行します。動作確認に便利です。
そのタスクが実行中の間はボタンは押せません。レコードが 1 件以上あれば、**最新のレコード**が
`{record_id}` などのレコード系プレースホルダーに使われるので、レコードを使うタスクもそのまま試せます。

## 4. トリガ（いつ実行するか）

トリガはダイアログの**ドロップダウン**で選びます。**開くと各項目に説明が表示**されるので、
迷ったら一覧を見比べてください。選択中のトリガの説明はドロップダウンの下にも出ます。

| トリガ | 発火タイミング | 入るプレースホルダー |
| --- | --- | --- |
| **キャプチャ開始時** | 画面キャプチャが開始されたとき（開始ボタン or 自動開始） | `event` |
| **キャプチャ停止時** | 画面キャプチャが停止したとき（停止ボタン or シーン終了） | `event` |
| **レコード取得時** | 認識が完了し、新しい殿堂入りレコードが 1 件確定したとき | `event`, `record_id` ＋ レコード系プレースホルダー（[5 章](#5-イベントデータとプレースホルダーrecord_id-など)） |
| **エクスポート完了時** | CSV / JSON / ZIP の書き出しが完了したとき | `event`, `export_path` |
| **他のタスク実行時** | 別のタスクの実行が完了したとき（タスクを連鎖させる） | `event`, `task_name`, `task_id`, `task_status` ＋ 元タスクから引き継いだプレースホルダー |
| **手動実行のみ** | 自動では発火しない。▶ ボタンを押したときだけ実行 | `event`（値は `manual`）＋ 最新レコードがあればレコード系プレースホルダー |

> **「レコード取得時」はキャプチャ 1 件ごとに 1 回**発火します。複数頭を続けてキャプチャすると、
> その都度タスクが走ります。

### 「他のタスク実行時」でタスクをつなげる

複数のアクションを順番に実行したいときは、タスクを分けて**連鎖**させます。

- このトリガを選ぶと、ダイアログに **「連鎖元のタスク」** ドロップダウンが出ます。指定したタスクの
  実行が**完了した直後**にこのタスクが走ります。**連鎖元の指定は必須**で、未選択のままでは保存できません
  （連鎖元を選ばないタスクは実行されないため）。
- 連鎖元タスクの**ペイロード（`{record_id}` など）はそのまま引き継がれます**。さらに連鎖元の
  `{task_name}` / `{task_id}` / `{task_status}` も使えます。
- 連鎖は**成功・失敗を問わず**、連鎖元タスクが**完了するたびに**発火します。連鎖先で結果に応じて
  分岐したいときは `{task_status}`（`success` / `failure` / `cancelled` / `timeout`）を使ってください。
- **同じタスクは 1 つの連鎖の中で 1 回しか走りません**。これによりタスク同士が互いを呼び合っても
  無限ループや際限のない多重実行になりません（保険として深さ 16 の上限もあります）。

> 例: 「レコード取得時」のタスク A（通知）と、「他のタスク実行時・連鎖元 = A」のタスク B（Webhook）を
> 作ると、取得 → 通知 → Webhook の順に実行されます。

## 5. イベントデータとプレースホルダー（`{record_id}` など）

トリガが発火すると、そのイベントの**データ**がアクションに渡されます。
データは**プレースホルダー**という名前付きの値で、アクションの文字列の中に `{プレースホルダー名}` と書くと、
実行時に実際の値へ置き換わります。

各入力欄（外部プログラムの引数欄・Webhook の URL／本文欄・内蔵アクションの内容欄）の下にある
**「プレースホルダーをコピー」ドロップダウン**から項目を選ぶと、その `{プレースホルダー}` が**クリップボードに
コピー**されるので、入力欄に貼り付けて使います。各項目にはプレースホルダー名と説明が表示され、選んだトリガに
応じて一覧が切り替わります。

| プレースホルダー | 意味 | 値が入るトリガ |
| --- | --- | --- |
| `{event}` | 発火したイベントの識別子（例: `record_captured`） | すべて |
| `{modules_dir}` | マスタデータ（`labels.json` などの ID→名称変換表）が入ったフォルダのパス | すべて |
| `{record_id}` | 取得した殿堂入りレコードの ID | レコード取得時のみ |
| `{export_path}` | 書き出されたファイルのパス | エクスポート完了時のみ |
| `{task_name}` `{task_id}` | 連鎖元のタスク名 / ID | 他のタスク実行時のみ |
| `{task_status}` | 連鎖元タスクの実行結果（`success` / `failure` / `cancelled` / `timeout`） | 他のタスク実行時のみ |

> `{record_json_path}`（後述）はレコードの数値 ID を多く含みます。`{modules_dir}` 配下の各変換表を
> 併せて渡せば、外部プログラム側でスキル名・因子名・キャラ名などへ解決できます。

さらに**「レコード取得時」トリガ**では、取得したレコードの内容が以下のプレースホルダーとして使えます
（一覧は選択中のトリガに応じて切り替わります。「他のタスク実行時」では元タスクから引き継いだプレースホルダーも出ます）。

| プレースホルダー | 意味 |
| --- | --- |
| `{record_dir}` | レコードの保存フォルダのパス |
| `{record_json_path}` | レコード本体 `record.json` のフルパス（各種 ID・ステータスを含む） |
| `{record_json}` | レコード本体 `record.json` の中身そのもの（JSON 文字列・各種 ID・ステータスを含む） |
| `{trainee_icon_path}` | 育成ウマ娘のアイコン画像（`trainee.jpg`）のフルパス |
| `{skill_image_path}` | スキル画面のキャプチャ画像（`skill.png`）のフルパス |
| `{factor_image_path}` | 因子画面のキャプチャ画像（`factor.png`）のフルパス |
| `{campaign_image_path}` | 育成成績画面のキャプチャ画像（`campaign.png`）のフルパス |

> レコード系プレースホルダーは、認識直後にレコードが見つからない場合でも `record.json` を直接読んで補完します。
> `record.json` には評価値・ステータス・各種 ID が含まれるので、`{modules_dir}` 配下の変換表と併せれば
> 外部プログラム側でキャラ名・ランク・シナリオ名などへ解決できます。

置換のルール:

- **そのトリガで値が入らないプレースホルダーは、空文字に置き換わります。**
  例: 「キャプチャ開始時」トリガで `{record_id}` を使っても空になります。
- **手動実行**では `{event}` が `manual` になり、`{export_path}` は空です。レコードが 1 件以上あれば
  **最新のレコード**で `{record_id}` とレコード系プレースホルダーが埋まります（レコードが無ければ空）。
  `{modules_dir}` などのモジュール系プレースホルダーは手動実行でも値が入ります。
- 定義していないプレースホルダー（例: `{foo}`）も空文字になります。

## 6. アクション：外部プログラム

アクション種別で **「外部プログラム」** を選ぶと、任意の実行ファイルを起動できます。

### 設定項目

| 項目 | 説明 |
| --- | --- |
| **プログラムのパス**（必須） | 起動する実行ファイル。📁 ボタンでファイル選択できます。 |
| **引数テンプレート** | コマンドライン引数。`{record_id}` などのプレースホルダーを埋め込めます。 |
| **カレントディレクトリ** | プログラムの作業ディレクトリ。📁 で選択。**空欄ならアプリと同じ場所**で実行します。 |
| **タイムアウト（秒・必須）** | この秒数を超えたら**子プロセスごと**強制終了します（シェル経由や `.bat` ラッパーで起動した本体も止まります）。**既定 30 秒**、空欄にはできません。 |
| **シェル経由で実行** | `.bat` ファイルや `echo` などのシェル組込みコマンドを使うときに ON にします。 |

### 引数テンプレートの書き方

引数は**スペースで区切られて 1 つずつ**プログラムに渡されます。プレースホルダーの置換は**区切りの後**に
行われるため、**値にスペースが含まれていても安全**です（勝手に分割されません）。

```
--input {export_path} --tag captured
```

プレースホルダーを**ダブルクォートで囲む**と、空白を含む値でも確実に 1 つの引数になります
（クォート自体は取り除かれます）。パスを渡すときの推奨形です。

```
"{export_path}"
```

> 引数は 1 つの文字列として丸ごと渡すのではなく、配列として安全に渡されます。
> シェルのリダイレクトやパイプ（`>` `|` など）を使いたい場合は **「シェル経由で実行」** を
> ON にしてください。

### 実行結果の扱い

- **標準出力・標準エラー出力は記録**され、履歴の詳細（[9 章](#9-実行履歴)）で確認できます。
  出力は日本語環境のコンソール（CP932）として解釈されます。長すぎる出力は途中までで打ち切られます。
- **終了コード 0 を成功**、それ以外を失敗として扱い、履歴に終了コードが残ります。
- タイムアウト・中止が起きた場合は、それぞれ「タイムアウト」「中止」として記録されます。

### アクション：Webhook（HTTP 送信）

アクション種別で **「Webhook（HTTP送信）」** を選ぶと、外部プログラムを書かずに HTTP リクエストを送れます。
Discord や Slack の Incoming Webhook への通知などに使えます。

| 項目 | 説明 |
| --- | --- |
| **URL**（必須） | 送信先。`{record_id}` などのプレースホルダーを埋め込めます。 |
| **メソッド** | `POST` / `GET` / `PUT` / `PATCH` / `DELETE`。`GET` では本文は送信されません。 |
| **本文の形式** | `JSON` / `フォーム` / `テキスト`。Content-Type ヘッダに反映されます。 |
| **本文** | リクエストボディ。プレースホルダーが置換されます。 |
| **タイムアウト（秒・必須）** | 接続・送受信のタイムアウト。**既定 30 秒**、空欄にはできません。 |

- 本文に埋め込んだ**プレースホルダーの値は本文の形式に合わせて自動でエスケープ**されます。`JSON` なら引用符・
  改行などを含む値でも JSON が壊れず、`フォーム` なら `&` / `=` を含む値が別フィールドとして混入しません
  （`テキスト` はそのまま送信）。`{"id": "{record_id}"}` のように、テンプレートの構造はそのまま、
  値だけが安全に挿入されます。
- 例外として **`{record_json}` は `JSON` 形式の本文ではエスケープされず、JSON 値としてそのまま埋め込まれます**。
  `{"record": {record_json}}` のように**引用符で囲まずに**使ってください（`"{record_json}"` と囲むと
  不正な本文になります）。なお `{record_json}` が空になるトリガで使うと本文が不正な JSON になるため、
  「レコード取得時」（またはそこからの連鎖）と組み合わせてください。
- **HTTP ステータス 2xx を成功**、それ以外を失敗として扱い、履歴にステータスコードが残ります。
- レスポンス本文は履歴の詳細で確認できます（長すぎる場合は打ち切られます）。
- タイムアウト・中止が起きた場合は、それぞれ「タイムアウト」「中止」として記録されます。

> 例（Discord）: メソッド `POST`、本文の形式 `JSON`、本文 `{"content": "新しいレコードを取得しました（{record_id}）"}`。

## 7. アクション：アプリ内蔵

アクション種別で **「アプリ内蔵アクション」** を選ぶと、用意済みの処理を実行できます。
内蔵アクションは**内容を指定**できます（プレースホルダー使用可のものは「プレースホルダーをコピー」ドロップダウンから貼り付け可）。

| 内蔵アクション | 動作 | 内容欄（既定値） |
| --- | --- | --- |
| **通知を表示** | アプリ内に通知（トースト）を出します | 通知メッセージ（既定 `{event}`、プレースホルダー可） |
| **クリップボードへコピー** | 指定した内容をクリップボードにコピーします | コピーする内容（既定 `{record_id}`、プレースホルダー可） |
| **画像をクリップボードへコピー** | レコードの画像を**画像として**コピーします | コピーする画像を**選択**（アイコン / スキル画面 / 因子画面 / 育成情報画面） |
| **ファイルをクリップボードへコピー** | レコードのファイルを**ファイル参照として**コピーします（エクスプローラ等に貼り付け可） | コピーするファイルを**選択**（各画像 / `record.json`） |
| **サウンドを鳴らす** | 効果音を再生します | サウンド種別を**選択**（通知音(標準) / 通知音(弱) / エラー音） |

> 画像・ファイル・サウンドの対象は**ドロップダウンで選択**します（自由入力ではありません）。
> 画像／ファイルのコピーには `record_id` が必要なため、**「レコード取得時」（または、そこから連鎖した
> 「他のタスク実行時」）以外のトリガと組み合わせると保存できません**（ダイアログに警告が表示されます）。

例:

- 「クリップボードへコピー」の内容欄に `{record_id}` → 取得したレコードの ID がコピーされます。
- 「通知を表示」の内容欄に `レコードを取得: {record_id}` → ID 入りの通知が出ます。
- 「画像をクリップボードへコピー」で「スキル画面」を選ぶ → スキル画面の画像がコピーされます。

## 8. 実行中の表示と中止

タスクが動いている間は **「実行中」カード**に行が追加され、進捗インジケータが回ります。

- アクションは進捗の割合を報告しないため、**不確定（くるくる）表示**になります。
- 行の **■ ボタン**で中止できます。**外部プログラムは子プロセスごと強制終了**、**Webhook は送信を中断**され、
  履歴に「中止」と残ります。
- 内蔵アクションは通常一瞬で終わります。中止すると実行枠は即座に解放されますが、
  実行中の処理自体はバックグラウンドで完了まで進みます。

---

## 9. 実行履歴

実行が終わると **「実行履歴」カード**に結果が 1 行追加されます（最新が上）。

各行に表示される情報:

- **状態アイコン**（色分け）: 成功＝緑、失敗＝赤、中止＝灰、タイムアウト＝橙
- **タスク名**
- **トリガ／実行時刻／所要時間**、外部プログラムは**終了コード**も
- **エラーや標準エラー出力がある行はタップ**すると詳細を表示します

右上の **「履歴を消去」** で全件削除できます。履歴は**最新 100 件**まで保持され、
それを超えると古いものから自動的に消えます。

## 10. 保存される場所と再起動後の動作

- **登録したタスク**と**実行履歴**はアプリ設定と同じ場所に保存され、**再起動後も残ります**。
- 「実行中」の情報だけは一時的なもので、アプリを閉じると消えます
  （実行中のまま閉じた場合、その外部プログラム自体の挙動は OS 側に委ねられます）。

## 11. レシピ集（そのまま使える例）

### 取得したレコードを外部ツールに自動連携

- トリガ: **レコード取得時**
- アクション: 外部プログラム
  - パス: 連携したいツールの実行ファイル
  - 引数: `--id {record_id}`

### 取得直後にレコード ID をクリップボードへ

- トリガ: **レコード取得時**
- アクション: クリップボードへコピー、内容 `{record_id}`

### エクスポート完了を通知（出力先つき）

- トリガ: **エクスポート完了時**
- アクション: 通知を表示、内容 `エクスポート完了: {export_path}`

### 書き出したファイルを Python スクリプトで後処理

- トリガ: **エクスポート完了時**
- アクション: 外部プログラム
  - パス: `python` の実行ファイル（または `.bat`）
  - 引数: `process.py "{export_path}"`
  - 必要に応じて **シェル経由で実行** を ON、**カレントディレクトリ**にスクリプトの場所を指定

### 取得を Discord に通知（外部プログラム不要）

- トリガ: **レコード取得時**
- アクション: Webhook
  - URL: Discord の Incoming Webhook URL
  - メソッド `POST`、本文の形式 `JSON`
  - 本文: `{"content": "新しいレコードを取得しました（{record_id}）"}`

### 取得直後にアイコンをコピーしてから通知（タスク連鎖）

2 つのタスクを作ってつなげます。

1. タスク A: トリガ **レコード取得時** / アクション「画像をクリップボードへコピー」で「アイコン」を選択
2. タスク B: トリガ **他のタスク実行時** / 連鎖元のタスク **= A** / アクション「通知を表示」、内容 `アイコンをコピーしました`

### 動作確認用の手動タスク

- トリガ: **手動実行のみ**
- アクション: 任意（まず「通知を表示」で試すのがおすすめ）。▶ ボタンで実行。

## 12. トラブルシューティング

| 症状 | 確認すること |
| --- | --- |
| タスクが自動で動かない | タスクが**有効**か／**トリガが目的のイベントと一致**しているか。手動 ▶ では動くか。 |
| 外部プログラムが起動しない（失敗になる） | **パスが正しい**か。`.bat` やシェルコマンドは **シェル経由で実行** が ON か。 |
| 引数が意図通り渡らない | スペースを含む値は**ダブルクォートで囲む**（例 `"{export_path}"`）。 |
| 出力が文字化けする | 出力は CP932 として解釈されます。プログラム側の出力エンコーディングを確認。 |
| `{record_id}` が空になる | そのトリガでは値が入りません（[5 章](#5-イベントデータとプレースホルダーrecord_id-など)の表を参照）。 |
| 終わらない／固まる | **タイムアウト（既定 30 秒）で自動的に打ち切られます**。すぐ止めたいときは実行中カードの ■ で中止。長い処理ならタイムアウト値を大きくする。 |
| 何がエラーか分からない | 履歴の該当行を**タップ**して標準エラー出力・エラー内容を確認。 |

## 13. 制限事項・今後の予定

現時点での仕様と、設計上は見据えているが未実装の項目です。

- **トリガは既存イベントに限定**: レコード追加・削除などはまだトリガにできません。
- **スケジュール（定期実行）は未対応**: 一定間隔・指定時刻での発火は今後の予定です。
- **スクリプトアクション（dart_eval）は未対応**: 将来、アクション種別として
  ユーザー定義スクリプトを追加できるよう設計してあります。

## 14. クイックリファレンス

**タスク** = トリガ + アクション。有効なタスクは、一致するトリガが来ると自動実行。

**トリガ**: キャプチャ開始時 / キャプチャ停止時 / レコード取得時 / エクスポート完了時 / 他のタスク実行時 / 手動実行のみ

**プレースホルダー**:

| プレースホルダー | 値が入るトリガ |
| --- | --- |
| `{event}` | すべて（手動は `manual`） |
| `{modules_dir}` | すべて（マスタデータのフォルダ） |
| `{record_id}` | レコード取得時 |
| `{export_path}` | エクスポート完了時 |
| `{task_name}` `{task_id}` `{task_status}` | 他のタスク実行時 |
| `{record_dir}` `{record_json_path}` `{record_json}` `{trainee_icon_path}` `{skill_image_path}` `{factor_image_path}` `{campaign_image_path}` | レコード取得時（他のタスク実行時にも引き継がれる場合あり） |

**アクション（外部プログラム）**: パス（必須） / 引数テンプレート / カレントディレクトリ / タイムアウト（必須・既定 30 秒） / シェル経由で実行
- 引数はスペース区切り。空白を含む値は `"{record_id}"` のようにダブルクォートで囲む。終了コード 0 が成功。

**アクション（Webhook）**: URL（必須） / メソッド / 本文の形式 / 本文 / タイムアウト（必須・既定 30 秒）。HTTP 2xx が成功。

**アクション（内蔵）**: 通知を表示 / クリップボードへコピー / 画像をクリップボードへコピー / ファイルをクリップボードへコピー / サウンドを鳴らす

**タスク連鎖**: 1 タスク = 1 アクション。複数アクションを順番に実行したいときは、「他のタスク実行時」
トリガで連鎖元タスクを指定（必須）してつなげる。ペイロードは引き継がれ、成功・失敗を問わず完了ごとに発火
（`{task_status}` で分岐可）。同じタスクは 1 連鎖につき 1 回まで（無限ループ防止、保険として深さ 16）。

**履歴**: 最新 100 件、再起動後も保持。行タップで出力詳細。
